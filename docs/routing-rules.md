## How to use this file

1. Every rule has an ID. Quote the ID when you ask for a change ("change H-07").
2. Every rule has a status:
   - **Decided**: Whitney confirmed it. Build it as written.
   - **Proposed**: the developer suggested it. Not final. Needs Whitney's yes.
   - **Open**: a question with no answer yet.
   - **Superseded**: replaced by a later rule. Kept for history, with a pointer to the new ID.
3. To change a rule, fill in the change report template at the bottom, add a row to the Changelog, and bump the document version. Rule text changes and the changelog entry go in the same commit.
4. Version numbers: the document version is `MAJOR.MINOR.PATCH`. Patch is wording fixes. Minor is a rule added or changed. Major is a rule removed or the meaning of the app changed.

## 1. Objective

Bridge Ride PDX is a free cycling route planner for Portland, Oregon, built around the Willamette River bridges, the Columbia River crossings to Vancouver, WA, and the bike and pedestrian bridges in between.

A rider should be able to say "go over the Hawthorne, come back on the Steel" and get the ride they meant, on the streets and paths they would actually choose: neighborhood greenways and car-free paths first, busy roads last. The app builds custom routes with stops and rules, saves and shares them, gives directions from the rider's live GPS position, and records the rides they have completed.

Principles:

1. Core route planning and saving stay free.
2. Portland first. Other places come later.
3. A route should match how a Portland rider thinks, not only how a map computes the shortest path.
4. The rider's words win: bridge nicknames, misspellings, and colors all work.
5. The rider's location stays on their device unless they share a route on purpose.

### 2.4 Stops

The first point is the start. After it, each stop is one of five types. Avoid is a rule, not a stop.

| ID | Ruling | Implementation | Status |
|---|---|---|---|
| T-01 | Stop: a place the rider stops. The route goes exactly there, in the order the rider sets. Optional time to stay. | Hard via point, snapped to the nearest bikeable road or path. | Decided |
| T-02 | Pass by: a place the rider rides past for the view, then keeps going. Soft. | See T-03 to T-06. | Decided |
| T-03 | The route is built without Pass by points first, then each one is slotted in where it adds the least distance. | Route the hard stops. For each Pass by, try every position between existing stops, keep the cheapest. Same riding style for the detour so a Pass by cannot pull the rider onto a high-stress road. | Decided |
| T-04 | Pass by counts when the route comes within 150 m. | Setting `pass_distance_m`, default 150, adjustable per point. Verify by closest-approach after routing. | Decided |
| T-05 | A Pass by may add at most 400 m. | Setting `detour_budget_m`, default 400, adjustable per point. | Decided |
| T-06 | When a Pass by does not fit, skip it and say so, with the extra distance. One click turns it into a Stop. | Message such as "Missed: Waterfront view, would add 1.2 km." | Decided |
| T-07 | Road: ride along this street, whole or a section, optionally in one direction. Hard. | Force entry at one end and exit at the other. If the street is not bikeable or the direction is impossible, say so and do not add it. | Decided |
| T-08 | Bridge: cross this bridge in this direction. Hard. | See B-03. | Decided |
| T-09 | Destination: the last place. One per route, always last. Options: loop back to start, or open end. | Final leg ends here. Dragging a new stop past it moves the Destination. | Decided |
| T-10 | Avoid: stay out of a street or an area. Applies to the whole route in any style. | Custom model area with priority multiplier 0, or block list. | Decided |

### 2.6 Street hierarchy

The rider's rule: some streets are better than others, and "better" has more than one meaning. The Eastbank Esplanade has no cars and a beautiful view of the Willamette, but it has traffic noise and some campers.

| ID | Ruling | Implementation | Status |
|---|---|---|---|
| H-01 | Every street and path belongs to one tier. | Tiers from best to worst: (1) car-free path, (2) neighborhood greenway, (3) protected lane, (4) bike lane, (5) low-traffic street, (6) shared busy road, (7) avoid. Tier comes from OSM road class, bike network, speed limit, and cycleway tags, plus city data later. | Proposed |
| H-02 | Tiers are the default ranking. A rider can still prefer a lower tier when it is much shorter. | Tier sets the base priority multiplier. Style changes how hard the tier is pushed. | Proposed |
| H-03 | A named corridor can carry its own ratings. | `data/corridors.json`: ways, ends, side of river, tier, ratings. Applied in the engine as a narrow polygon or by OSM way ID, with a road-class filter. | Proposed |
| H-04 | Ratings use five dimensions, each 1 (worst) to 5 (best): safety from cars, scenery, noise, comfort and conditions (crowding, campers), surface. | Fields `safety_from_cars`, `scenery`, `noise`, `comfort`, `surface`. | Proposed |
| H-05 | Each style weights the dimensions differently. Scenic leans on scenery. Low stress leans on safety and comfort. Fastest safe barely uses scenery. | Weight table per style, not yet written. Combine into one priority multiplier per corridor. | Open |
| H-06 | Each rider can change the weights in their route preference settings. | Per-rider weights override the style defaults. Stored with the rider's settings. | Open |
| H-07 | Eastbank Esplanade starter ratings: safety 5, scenery 5, noise 2, comfort 3, surface 4. | Numbers are the developer's proposal from Whitney's description (no cars, beautiful view, traffic noise, some campers). Surface is a placeholder. Whitney has not confirmed any number. | Proposed |
| H-08 | When the rider is on the east side, the Eastbank Esplanade is the preferred route for north-south and south-north movement. | Corridor flag `ns_spine`. Boost the corridor when the trip is mostly north-south and the rider is east of the river. Needs a definition of "mostly north-south" (for example, bearing within 45 degrees of north or south) and a cap on how far off line the route may go to reach it. | Proposed |
| H-09 | Does H-08 apply to every style, or only to some? | Candidate: Greenway first, Scenic, Low stress. Not decided. | Open |
| H-10 | Are there other east-side north-south spines to add? | None identified. Ask Whitney. | Open |
| H-11 | Campers and crowding lower comfort but do not close a corridor. | Comfort is a rating, not an exclusion. | Proposed |
| H-12 | Map the tiers onto Metro's Bike There categories where the data allows: Established Bikeway, Bike Friendly Street, Designated Bike Lane, Helpful Connection, Bike with Caution, Unpaved Trail. | License and coverage of the Metro data are unchecked. | Open |

### 2.9 Where the rider is (location context)

Before a search, the app works out where the rider is so it can show nearby bridges and bike routes. Then it waits for a search, or follows a route the rider has started.

| ID | Ruling | Implementation | Status |
|---|---|---|---|
| L-01 | East or west side: the Willamette River divides east from west. | Same rule as Portland addresses (City Code 17.92.020). Prototype: compare the rider's longitude with a river centerline interpolated through the bridge midpoints, by latitude. Better: point-in-polygon against the OpenStreetMap Willamette water area. North of the Columbia is Vancouver, WA. | Proposed |
| L-02 | North or south: Burnside Street divides north from south. | City Code 17.92.020. Burnside Bridge midpoint is at latitude 45.5232. East of the river, north of Oregon St and west of Williams Ave is the North (N) section. | Proposed |
| L-03 | The rider's bridge band is the two bridges north and south of them. | Project the position onto the river line and find the bridges on each side by latitude (`position.north_neighbor` / `south_neighbor`). | Proposed |
| L-04 | Show the bike routes nearest the rider that lead to the most-used bike routes. | Rank nearby paths and bike routes (tier H-01 first, then network distance, not straight-line distance). | L-05 | Distances near the river use routing distance, never straight lines. | A bridge 300 m away across the water can be 3 km by bike. Use the engine (or a precomputed matrix) for "nearest". | Proposed |
| L-06 | App states: Idle (context shown), Search, Preview, Following, Off route, Arrived. | Idle refreshes context about every 30 s or 100 m of movement. Following starts only when the rider presses Start. | Proposed |

### 2.12 Keeping the route through GPS gaps

Signal is expected to drop near and under bridges (lower decks, the Esplanade under bridge decks, MAX structures).

| ID | Ruling | Implementation | Status |
|---|---|---|---|
| P-01 | The active route survives everything: signal loss, the app closing, the phone restarting. | Save route ID, leg index, distance along route, and the last good fix (time, position, accuracy, speed, heading) to local storage every 5 s and on every state change. On start, offer "Resume ride". | Proposed |
| P-02 | During a gap, show a rough position: the last known point moved forward along the route at the last speed. | Dead reckoning along the route only (never off-route). Show it as "estimated" with an uncertainty circle that grows with time. Cap at 60 s or 300 m, then hold and show "Searching for GPS". | Proposed |
| P-03 | No reroute and no off-route warning while the position is estimated. | Off-route detection (N-04) runs only on real fixes with accuracy of 30 m or better. | Proposed |
| P-04 | When fixes return, rejoin the route ahead of the last progress, not behind it. | Map-match the new fix to the route within a window ahead of the last progress, weighting heading. Prevents snapping to the parallel lane, the deck above, or the path below. Accept backward jumps only after several consistent fixes. | Proposed |
| P-05 | Known low-signal zones widen tolerances. | Zones: Steel lower deck, Esplanade under the Morrison, Burnside, and Hawthorne decks, Tilikum MAX area. Inside a zone, off-route needs 5 readings at 60 m. | Proposed |
| P-06 | Deck or below: use the phone's barometer as a tiebreaker. | The S24 Ultra has a pressure sensor. A change of a few meters separates a deck from the path below. | Proposed |
| P-07 | A stale "last location" is a hint, never the truth. | Android `getLastLocation()` can be old or null; use `getCurrentLocation()` for a fresh fix (Android developer docs). Show its age. | Decided |
| P-08 | Battery savers can stop GPS when the screen is off. | Covered by N-06 and N-07 (foreground service, Samsung battery settings). Google Maps lists battery saver as a cause of "GPS signal lost". | Decided |
