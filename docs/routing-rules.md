## How to use this file

1. Every rule has an ID. Quote the ID when you ask for a change ("change H-07").
2. Every rule has a status:
   - **Decided**: Whitney confirmed it. Build it as written.
   - **Proposed**: the developer suggested it. Not final. Needs Whitney's yes.
   - **Open**: a question with no answer yet.
   - **Superseded**: replaced by a later rule. Kept for history, with a pointer to the new ID.
3. To change a rule, fill in the change report template at the bottom, add a row to the Changelog, and bump the document version. Rule text changes and the changelog entry go in the same commit.
4. Version numbers: the document version is `MAJOR.MINOR.PATCH`. Patch is wording fixes. Minor is a rule added or changed. Major is a rule removed or the meaning of the app changed.

## 1. Objective

Bridge Ride PDX is a free cycling route planner for Portland, Oregon, built around the Willamette River bridges.

A rider should be able to say "go over the Hawthorne, come back on the Steel" and get the ride they meant, on the streets and paths they would actually choose: neighborhood greenways and car-free paths first, busy roads last. The app builds custom routes with stops and rules, saves and shares them, gives directions from the rider's live GPS position, and records the rides they have completed.

Principles:

1. Core route planning and saving stay free.
2. Portland first. Other places come later.
3. A route should match how a Portland rider thinks, not only how a map computes the shortest path.
4. The rider's words win: bridge nicknames, misspellings, and colors all work.
5. The rider's location stays on their device unless they share a route on purpose.

## 2. Rules

Columns: ID, Ruling (plain language), Implementation (developer), Status.

### 2.1 General

| ID | Ruling | Implementation | Status |
|---|---|---|---|
| G-01 | Creating, saving, and editing routes is free. Paid features, if any, are extras such as themed rides. | No account or paywall in the prototype. Routes saved locally (SQLite). | Decided |
| G-02 | Portland first. | Map extract is BBBike Portland. Rides elsewhere (for example Banks-Vernonia) can be logged but not routed until a larger Oregon extract is added. | Decided |
| G-03 | A saved route never changes on its own. | Store the drawn path with the route. A Re-route button recalculates on request. Keep previous versions for undo. | Decided |
| G-04 | Start on a PC, then the phone. | TypeScript web app (MapLibre) first. Python only for scripts. Phone is a Samsung S24 Ultra (Android). Dev PC runs Windows. | Decided |

### 2.2 Safety

| ID | Ruling | Implementation | Status |
|---|---|---|---|
| S-01 | Put cars on car-heavy roads and bikes on bike-heavy roads. | Bike profile weights down TRUNK, PRIMARY, SECONDARY, TERTIARY. See `routing/greenway_first.json`. | Decided |
| S-02 | Car routing stays away from bike-heavy routes. | Out of scope until the app gives driving directions. Recorded so it is not forgotten. | Open |
| S-03 | Avoid Streetcar and MAX tracks, or cross them at a safe angle only. | Needs a track layer. OSM `railway=tram` ways crossing bike ways. Not built. | Proposed |
| S-04 | Penalize unprotected left turns across busy roads and unsignaled arterial crossings. Prefer signals and islands. | Turn penalties in the custom model, or a post-check. Not built. | Proposed |
| S-05 | Avoid stairs and walk-your-bike sections when asked. | `Dismount` modifier excludes `highway=steps` and `bicycle=dismount`. | Proposed |
| S-06 | At night, prefer lit roads and paths. | `Night` modifier boosts `lit=yes`. | Proposed |

### 2.3 Bridges

| ID | Ruling | Implementation | Status |
|---|---|---|---|
| B-01 | A bridge is a crossing in one direction, not a single point. | Each bridge has `eastbound` (west approach to east approach) and `westbound` (the reverse). See `data/bridges.json`. | Decided |
| B-02 | Every bridge has two GPS positions, one on each side, so the router can cross it. | Points are `[lat, lon]`, about 60 m outside each bridge end, so they snap to the street or path rather than the deck. Generated by `tools/extract_bridges.py` and `tools/build_bridges.py`. | Decided |
| B-03 | A Bridge stop forces the approach, then the exit, in the chosen direction. | Insert the two points as ordered via points. The engine must be allowed to snap onto bridges: `routing.snap_preventions_default: tunnel, ferry` (not `bridge`). | Decided |
| B-04 | Riders can name a bridge any common way: nickname, street name, misspelling, or color. All resolve to the same bridge. | `data/bridge_names.json` holds names, aliases, misspellings, colors. `tools/match_bridge.py`: normalize, drop words like "the" and "bridge", exact match, then color, then fuzzy match. Test cases in `data/bridge_match_cases.json` (29 of 29 pass). | Decided |
| B-05 | A color word alone returns every bridge with that color, and the app asks which one. | "green bridge" returns Fremont, Hawthorne, and St. Johns. "red bridge" returns Broadway. Colors come from Wikipedia photo captions, not paint specs. | Decided |
| B-06 | Bridges closed to bikes are never offered. | `bike_access: no` for Fremont and Marquam (OSM `motorway`, `bicycle=no`). | Decided |
| B-07 | The Ross Island Bridge: do not offer it until a rider confirms it is rideable. | `bike_access: limited`. OSM marks one way bicycle-discouraged and the engine avoids it, failing validation both directions. | Open |
| B-08 | Steel Bridge: use the lower deck paths. | The east approach sits on N Oregon St. Westbound validation fails (x2.58 detour). The east approach point needs hand tuning. | Open |
| B-09 | A bridge's crossing is checked by routing it both ways. | Pass when the route follows the bridge geometry for at least 50% of the span and the detour ratio is at most 1.8. Run `tools/validate_bridges.py` with the engine up. Result on 2026-10-23: 15 of 18 offered crossings pass. | Decided |
| B-10 | The "Bridge of the People" nickname for Tilikum Crossing needs a source. | Alias is in `bridge_names.json` from memory. Verify or remove. | Open |
| B-11 | Official bridge codes are kept for matching with county data. | Multnomah County Bridges layer. Codes entered: Broadway 06757, Burnside 00511, Morrison 02758, Hawthorne 02757, Sellwood 21493. Others null. License of the layer is not stated. | Decided |

### 2.4 Stops

The first point is the start. After it, each stop is one of five types. Avoid is a rule, not a stop.

| ID | Ruling | Implementation | Status |
|---|---|---|---|
| T-01 | Stop: a place the rider stops. The route goes exactly there, in the order the rider sets. Optional time to stay. | Hard via point, snapped to the nearest bikeable road or path. | Decided |
| T-02 | Pass by: a place the rider rides past for the view, then keeps going. Soft. | See T-03 to T-06. | Decided |
| T-03 | The route is built without Pass by points first, then each one is slotted in where it adds the least distance. | Route the hard stops. For each Pass by, try every position between existing stops, keep the cheapest. Same riding style for the detour so a Pass by cannot pull the rider onto a high-stress road. | Decided |
| T-04 | Pass by counts when the route comes within 150 m. | Setting `pass_distance_m`, default 150, adjustable per point. Verify by closest-approach after routing. | Decided |
| T-05 | A Pass by may add at most 400 m. | Setting `detour_budget_m`, default 400, adjustable per point. | Decided |
| T-06 | When a Pass by does not fit, skip it and say so, with the extra distance. One click turns it into a Stop. | Message such as "Missed: Waterfront view, would add 1.2 km." | Decided |
| T-07 | Road: ride along this street, whole or a section, optionally in one direction. Hard. | Force entry at one end and exit at the other. If the street is not bikeable or the direction is impossible, say so and do not add it. | Decided |
| T-08 | Bridge: cross this bridge in this direction. Hard. | See B-03. | Decided |
| T-09 | Destination: the last place. One per route, always last. Options: loop back to start, or open end. | Final leg ends here. Dragging a new stop past it moves the Destination. | Decided |
| T-10 | Avoid: stay out of a street or an area. Applies to the whole route in any style. | Custom model area with priority multiplier 0, or block list. | Decided |

### 2.5 Routing styles and modifiers

| ID | Ruling | Implementation | Status |
|---|---|---|---|
| Y-01 | Greenway first: strongly prefers greenways, paths, and bike boulevards. Accepts a longer route. | Profile `greenway_first` (`routing/greenway_first.json`). Current weights: CYCLEWAY x1.6, bike network x1.3, residential or living street with speed 40 or less x1.2, TERTIARY x0.9, SECONDARY x0.7, PRIMARY x0.5, TRUNK x0.3. | Decided |
| Y-02 | Balanced: greenways when the detour is small, direct otherwise. | Profile `bike` (built in). | Decided |
| Y-03 | Fastest safe: shortest route that still avoids high-stress roads. | Not built. | Decided |
| Y-04 | Low stress: avoid high speed limits, many lanes, and no bike lane. | Not built. | Decided |
| Y-05 | Flat: penalize climbing, with a maximum grade setting. | Needs elevation (SRTM). Not tested; the sandbox could not download it. Test on the PC. | Decided |
| Y-06 | Scenic: prefer riverfront, parks, and paths. | Not built. Uses the scenery dimension (H-04). | Decided |
| Y-07 | Round trip: give a start, a distance or time, and a direction. Returns a loop. | GraphHopper round_trip algorithm. Not built. | Decided |
| Y-08 | Smooth surface: avoid gravel, cobbles, and rough paving. | `surface` encoded value. Not built. | Decided |
| Y-09 | Modifiers work on top of any style: tracks (S-03), intersections (S-04), dismount (S-05), no backtracking, climb budget, night (S-06), and up to three alternatives with distance, time, climb, and a stress score. | Not built. | Decided |
| Y-10 | A style alone does not reproduce how a rider rides. Bridge stops and via points decide which side of the river and which bridge. | Test ride 6 and 13 findings (section 3.2). | Decided |

### 2.6 Street hierarchy

The rider's rule: some streets are better than others, and "better" has more than one meaning. The Eastbank Esplanade has no cars and a beautiful view of the Willamette, but it has traffic noise and some campers.

| ID | Ruling | Implementation | Status |
|---|---|---|---|
| H-01 | Every street and path belongs to one tier. | Tiers from best to worst: (1) car-free path, (2) neighborhood greenway, (3) protected lane, (4) bike lane, (5) low-traffic street, (6) shared busy road, (7) avoid. Tier comes from OSM road class, bike network, speed limit, and cycleway tags, plus city data later. | Proposed |
| H-02 | Tiers are the default ranking. A rider can still prefer a lower tier when it is much shorter. | Tier sets the base priority multiplier. Style changes how hard the tier is pushed. | Proposed |
| H-03 | A named corridor can carry its own ratings. | `data/corridors.json`: ways, ends, side of river, tier, ratings. Applied in the engine as a narrow polygon or by OSM way ID, with a road-class filter. | Proposed |
| H-04 | Ratings use five dimensions, each 1 (worst) to 5 (best): safety from cars, scenery, noise, comfort and conditions (crowding, campers), surface. | Fields `safety_from_cars`, `scenery`, `noise`, `comfort`, `surface`. | Proposed |
| H-05 | Each style weights the dimensions differently. Scenic leans on scenery. Low stress leans on safety and comfort. Fastest safe barely uses scenery. | Weight table per style, not yet written. Combine into one priority multiplier per corridor. | Open |
| H-06 | Each rider can change the weights in their route preference settings. | Per-rider weights override the style defaults. Stored with the rider's settings. | Open |
| H-07 | Eastbank Esplanade starter ratings: safety 5, scenery 5, noise 2, comfort 3, surface 4. | Numbers are the developer's proposal from Whitney's description (no cars, beautiful view, traffic noise, some campers). Surface is a placeholder. Whitney has not confirmed any number. | Proposed |
| H-08 | When the rider is on the east side, the Eastbank Esplanade is the preferred route for north-south and south-north movement. | Corridor flag `ns_spine`. Boost the corridor when the trip is mostly north-south and the rider is east of the river. Needs a definition of "mostly north-south" (for example, bearing within 45 degrees of north or south) and a cap on how far off line the route may go to reach it. | Proposed |
| H-09 | Does H-08 apply to every style, or only to some? | Candidate: Greenway first, Scenic, Low stress. Not decided. | Open |
| H-10 | Are there other east-side north-south spines to add? | None identified. Ask Whitney. | Open |
| H-11 | Campers and crowding lower comfort but do not close a corridor. | Comfort is a rating, not an exclusion. | Proposed |
| H-12 | Map the tiers onto Metro's Bike There categories where the data allows: Established Bikeway, Bike Friendly Street, Designated Bike Lane, Helpful Connection, Bike with Caution, Unpaved Trail. | License and coverage of the Metro data are unchecked. | Open |

### 2.7 Navigation and GPS

| ID | Ruling | Implementation | Status |
|---|---|---|---|
| N-01 | Handle momentary GPS drops and low-confidence positions. | Hold the last good position through short dropouts. Mark the position stale after a timeout. Test with a recorded ride that has a 10 second gap. | Decided |
| N-02 | Use heading, not position alone. | Use route direction for heading when moving slowly. Use device heading otherwise. | Decided |
| N-03 | Smooth the readings and snap them to the route. | Pure logic with no map code, so it can be tested by replaying GPX traces. | Decided |
| N-04 | Off route means several bad readings in a row, not one. | Start at 40 m from the route for 3 readings. Tune by replay. | Proposed |
| N-05 | When off route, reroute from the current position in the same style. The saved route stays unchanged. | New route is a session route. Offer to save it. | Decided |
| N-06 | Ride tracking keeps running when the phone locks. | Android foreground service of type location. Ask for permission at Start ride. Resume the exact route after lock. | Decided |
| N-07 | Samsung battery settings can stop tracking. Guide the rider through them. | Checklist: battery not optimized for the app, not on sleeping apps, start in the foreground before locking. | Decided |
| N-08 | Decision gate: ride 30 minutes in the web app with the screen locked for 10. If track gaps exceed 10 seconds, build the Ride screen natively in Kotlin. | One test, one pass or fail. | Decided |

### 2.8 Data, sharing, and privacy

| ID | Ruling | Implementation | Status |
|---|---|---|---|
| D-01 | Location history stays on the device. | Nothing uploaded in the prototype. | Decided |
| D-02 | A shared route has its start and end trimmed and the distance rounded. | Compute the shared distance from the trimmed route only. A privacy zone that reports the full distance leaks the endpoints. | Decided |
| D-03 | Credit OpenStreetMap. | "(c) OpenStreetMap contributors, ODbL" in the app and in generated data files. | Decided |
| D-04 | Look up addresses politely. | Nominatim policy: 1 request per second, no autocomplete, cache results, identify the app. Use a local geocoder later if usage grows. | Decided |
| D-05 | The ride log holds completed rides. | Fields: name, date, distance, notes, tags, linked route (optional), GPX (optional). A saved route is Planned until marked ridden. A route can be ridden many times. | Decided |
| D-06 | Official city data (PBOT Recommended Bicycle Routes, PortlandMaps layer 183) may become a boost layer. | No license is listed on the layer. Do not ship the data until the license is known. | Open |

## 7. Change report template

Copy this block to the top of the Changelog, fill it in, and change the rule rows in section 2 in the same commit.

```
### YYYY-MM-DD, doc version X.Y.Z

- Reporter: (who asked for the change)
- Rules touched: (IDs, for example H-07, B-07)
- What changed (plain language): (one or two sentences a rider would understand)
- Why: (the ride, problem, or decision behind it)
- Developer notes: (files changed, engine settings, data regenerated, tests run)
- GitHub version: (short commit hash, tag, or PR number; "pending" until pushed)
- Status after change: (Decided, Proposed, Open, Superseded)
- Test rides affected: (ride numbers from docs/test-rides.md, or none)
- Replaces: (old rule ID, if this supersedes one)
```

Example of a filled entry:

```
### 2026-11-02, doc version 0.2.0

- Reporter: Whitney Hale

- Developer notes: data/corridors.json ratings updated. ns_spine limited to two styles. Re-ran rides 6 and 13.
- GitHub version: a1b2c3d
- Status after change: Decided
- Test rides affected: 6, 13
- Replaces: none
```
